# ESPHome configuration for esp32c6 LP core

This document describes the current ESPHome-side integration for the working
`lp_blink` LP-core binary. The setup now uses a local external component,
which is compatible with current ESPHome releases and avoids the removed
`custom_component` path.

This configuration has been verified to compile, upload, and run on-device with
the YAML defaults of a 30 ms pulse every 1000 ms.

## Build and refresh the LP binary

1. Build the LP project in `lp_blink/`:

```bash
idf.py set-target esp32c6
idf.py build
```

2. Copy the current raw LP binary into the ESPHome external component:

```powershell
Copy-Item lp_blink\build\esp-idf\ulp_blink\ulp_main\ulp_main.bin esphome\my_components\lp_blink\ulp_main.bin -Force
```

Just for tracking, copy the assembly .S file over even though it is not used.
```powershell
Copy-Item lp_blink\build\ulp_main.bin.S esphome\my_components\lp_blink\ulp_main.bin.S -Force
```

3. Regenerate the embedded byte-array header used by the working ESPHome build:

```powershell
$bytes = [System.IO.File]::ReadAllBytes('esphome\my_components\lp_blink\ulp_main.bin')
$hex = ($bytes | ForEach-Object { ('0x{0:x2}' -f $_) }) -join ', '
$content = @"
#pragma once

#include <cstddef>
#include <cstdint>

namespace esphome {
namespace lp_blink {

inline constexpr uint8_t kUlpMainBinary[] = {
$hex
};

inline constexpr size_t kUlpMainBinarySize = sizeof(kUlpMainBinary);

}  // namespace lp_blink
}  // namespace esphome
"@
Set-Content -LiteralPath 'esphome\my_components\lp_blink\ulp_main_binary.h' -Value $content -NoNewline
```

If you rebuild `lp_blink` and the LP shared-variable layout changes, also update
`esphome/my_components/lp_blink/ulp_main_shared.h` to match the new addresses in
`lp_blink/build/esp-idf/ulp_blink/ulp_main/ulp_main.ld`.

## ESPHome file layout

- `esphome/esp32c6_ulp_blink.yaml` contains the example YAML
- `esphome/my_components/lp_blink/__init__.py` defines the ESPHome config schema
- `esphome/my_components/lp_blink/lp_blink_component.h` declares the component
- `esphome/my_components/lp_blink/lp_blink_component.cpp` mirrors `lp_blink_start()` behavior
- `esphome/my_components/lp_blink/ulp_main.bin` is the copied raw LP binary from the ESP-IDF build
- `esphome/my_components/lp_blink/ulp_main_binary.h` is the generated byte-array header used by the working ESPHome build
- `esphome/my_components/lp_blink/ulp_main_shared.h` maps the current RTC shared variables

The current working build does not rely on `ulp_main.bin.S`. That file can be
kept as a reference artifact from the LP build, but the external component now
loads the binary from `ulp_main_binary.h`.

## Build notes

- The ESPHome component re-enables ESP-IDF's built-in `ulp` component because ESPHome excludes it by default.
- The ESPHome component sets `CONFIG_ULP_COPROC_ENABLED=y`, `CONFIG_ULP_COPROC_TYPE_LP_CORE=y`, and `CONFIG_ULP_COPROC_RESERVE_MEM=4096` to match the working ESP-IDF project.
- The LP payload is compiled into the firmware as a C++ byte array, which avoids assembler path problems seen with `.incbin` and standalone `.S` wrappers in the ESPHome build environment.

## YAML template

Adjust `ssid`, `password`, and `board` for your device.

```yaml
substitutions:
  lp_blink_pin: "4"

external_components:
  - source:
      type: local
      path: my_components

esphome:
  name: esp32c6_ulp_blink

esp32:
  variant: esp32c6
  board: esp32-c6-devkitc-1
  framework:
    type: esp-idf

logger:
  level: DEBUG

wifi:
  ssid: "your_ssid"
  password: "your_password"

lp_blink:
  id: lp_blink_component
  gpio_num: ${lp_blink_pin}
  init_state: last
  pulse_width_us: 30000
  wake_period_ms: 1000

number:
  - platform: template
    name: "LP Pulse Width (us)"
    id: lp_pulse_width_us
    min_value: 1000
    max_value: 100000
    step: 1000
    optimistic: true
    initial_value: 30000
    set_action:
      lambda: |-
        id(lp_blink_component).set_pulse_width_us((uint32_t) x);

  - platform: template
    name: "LP Wake Period (ms)"
    id: lp_wake_period_ms
    min_value: 100
    max_value: 5000
    step: 100
    optimistic: true
    initial_value: 1000
    set_action:
      lambda: |-
        id(lp_blink_component).set_wakeup_period_ms((uint32_t) x);

switch:
  - platform: template
    name: "LP Blink Enabled"
    lambda: |-
      return id(lp_blink_component).is_running();
    turn_on_action:
      lambda: |-
        id(lp_blink_component).start_blink();
    turn_off_action:
      lambda: |-
        id(lp_blink_component).stop_blink();
```

## Component behavior

- The component validates that `gpio_num` is RTC-capable before starting the LP core.
- It loads the LP binary with `ulp_lp_core_load_binary()` and starts it with `ulp_lp_core_run()`.
- It writes `flash_lp_io`, `pulse_width_us`, and `run_count` directly through the shared RTC addresses, matching the working `lp_blink_runtime.c` flow.
- `init_state` controls the startup policy: `running`, `stopped`, or `last`.
- The `last` policy stores the requested running/stopped state in RTC memory so it can be restored after deep sleep.
- Pulse width updates are applied in place.
- Wake-period updates restart the LP core only if it is currently running.
- `stop_blink()` uses `ulp_lp_core_stop()`, which is the supported HP-side way to stop LP-core wakeups.
- `start_blink()` uses the existing `ulp_lp_core_run()` startup path to resume blinking; there is no public HP-side `ulp_lp_core_lp_timer_enable()` or `ulp_lp_core_timer_start()` API in current ESP-IDF.

If `init_state: last` is selected and no valid saved RTC state exists yet, the component falls back to `running`.

## Notes

- The local external component is the supported replacement for removed `custom_component` usage in recent ESPHome releases.
- If `ulp_main.bin` changes, regenerate `ulp_main_binary.h` before rebuilding ESPHome.
- If the LP shared-memory symbol layout changes, update `ulp_main_shared.h` before rebuilding ESPHome.
